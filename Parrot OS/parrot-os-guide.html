SECTION 01 // FOUNDATION KNOWLEDGE

LINUX BASICS

Before you install a single tool, you need to understand how Linux works internally. These concepts appear in every single installation method.

CONCEPT // WHAT IS LINUX
Linux Is An Operating System Kernel
Linux is an open-source operating system kernel. Parrot OS is a Linux distribution (distro) — a full operating system built on top of the Linux kernel. Think of the kernel as the engine, and Parrot OS as the full car.

Parrot OS is built specifically for cybersecurity professionals. It comes with hundreds of pre-installed security tools, and you can add more anytime.
CONCEPT // THE TERMINAL
The Terminal Is Your Superpower
The terminal (also called command line, shell, or bash) is a text interface to your operating system. Instead of clicking buttons, you type commands.

To open it in Parrot OS: Right-click Desktop → Open Terminal or press Ctrl+Alt+T.

The terminal runs a program called bash (Bourne Again SHell) by default.
CONCEPT // SUDO
What Is sudo?
sudo stands for Superuser DO. It temporarily grants you administrator (root) privileges for one command.

Think of it like: your normal user account is a worker, root is the boss. sudo lets you temporarily become the boss to install software, modify system files, etc.

Without sudo, you cannot install software or modify critical files. You'll be asked for your password.
CONCEPT // DIRECTORIES
Linux Directory Structure
Everything in Linux is organized into directories (folders). The root directory is /. All other directories branch from it.

/home/username → Your personal files
/usr/bin → Where most programs live
/etc → Configuration files
/opt → Optional/third-party software
/tmp → Temporary files
CONCEPT // THE PATH VARIABLE
What Is $PATH?
$PATH is an environment variable that tells your system where to look for programs when you type a command.

When you type nmap, Linux doesn't search the entire hard drive. It only looks in the directories listed in your $PATH variable, in order.

Common PATH directories: /usr/bin, /usr/local/bin, /usr/sbin, ~/.local/bin, ~/go/bin

If a tool isn't found, it's often a PATH issue.
CONCEPT // PACKAGE MANAGER
What Is A Package Manager?
A package manager is like an app store for Linux. It handles downloading, installing, updating, and removing software.

Parrot OS uses APT (Advanced Package Tool). APT downloads packages from repositories — servers that store software collections.

Other package managers: pip for Python, go install for Go, snap, flatpak.
CONCEPT // REPOSITORIES
What Is A Repository?
A repository (repo) is a server that stores software packages. When you run apt install, APT connects to these servers to download the software.

Repository sources are listed in: /etc/apt/sources.list and /etc/apt/sources.list.d/

Parrot OS has its own repositories pre-configured with hundreds of security tools ready to install.
CONCEPT // DEPENDENCIES
What Are Dependencies?
A dependency is a library or program that another program needs to function. Like how a car needs an engine to run.

When you install a tool, APT automatically installs all its dependencies. This is called dependency resolution.

If you install manually (GitHub, pip, source), you often need to install dependencies yourself.

CONCEPT // BINARY
What Is A Binary?
A binary is an executable file — a compiled program that your CPU can run directly. When you install a tool, the installed file in /usr/bin/ is the binary.

Source code (.c, .cpp, .go files) must be compiled into a binary before the CPU can execute it. Some languages (Python) are interpreted instead — they run through an interpreter program.
SECTION 02 // PRIMARY METHOD

APT PACKAGE MANAGER

APT is the official, recommended, and easiest way to install tools on Parrot OS. Start here for any tool that is available in Parrot repositories.

WORKFLOW // APT INSTALLATION FLOW
How APT Works Internally
When you run apt install [tool], here's what happens inside Linux:

1. APT reads /etc/apt/sources.list to find repository servers
2. APT queries the package database at /var/lib/apt/lists/
3. APT resolves all dependencies
4. APT downloads .deb packages to /var/cache/apt/archives/
5. APT passes packages to dpkg for actual installation
6. dpkg extracts files to correct locations (/usr/bin/, /etc/, etc.)
7. dpkg records the installation in /var/lib/dpkg/status

Step 1: Update Package Lists

Before installing anything, always update your package lists. This downloads the latest information about available packages from all repositories.

sudo apt update ▼ CLICK TO EXPLAIN EACH PART
sudo
Superuser Do — runs the following command as root (administrator). Required to modify system packages.
apt
Advanced Package Tool — the package manager for Debian/Ubuntu/Parrot OS systems.
update
Sub-command: "refresh the package index." Downloads updated lists from all repositories. Does NOT install anything.
What happens internally: APT reads /etc/apt/sources.list and every file in /etc/apt/sources.list.d/. For each repository URL, it connects to the server and downloads a Packages.gz file containing the list of all available packages and their versions. These lists are saved to /var/lib/apt/lists/. This is how APT knows what's available before you install.

Important: update ≠ upgrade. update only refreshes the list of what's available. It does not upgrade installed software.

Step 3: Install A Tool

sudo apt install nmap -y ▼ EXPLAIN
sudo
Required — installing modifies system files, so root access is needed.
apt
The Advanced Package Tool package manager
install
Sub-command to install one or more packages
nmap
The exact package name to install. You can list multiple: nmap nikto gobuster
-y
Short for --yes. Automatically answers "yes" to all prompts. Skips the "Do you want to continue?" question.
What happens internally:
1. APT checks /var/lib/apt/lists/ for package metadata
2. APT builds a dependency graph — finds ALL packages nmap needs
3. Downloads .deb files to /var/cache/apt/archives/
4. dpkg extracts each .deb and places files:
   • Binary: /usr/bin/nmap
   • Data files: /usr/share/nmap/
   • Man page: /usr/share/man/man1/nmap.1.gz
5. dpkg records install in /var/lib/dpkg/status

SECTION 03 // LATEST CUTTING-EDGE TOOLS

INSTALLING FROM GITHUB

Many security tools are published directly on GitHub before (or instead of) being added to APT repositories. This method gets you the latest versions directly from developers.

CONCEPT // GIT
What Is Git and GitHub?
Git is a version control system — it tracks changes to code over time. GitHub is a website that hosts Git repositories.

When you git clone, you download a complete copy of the repository (all source files) to your computer. Many hackers publish their tools on GitHub, making it the go-to source for cutting-edge tools.

Step 1: Install Git (if not present)

INSTALL GIT
$sudo apt install git -y

Step 2: Clone The Repository

git
The Git version control command
clone
Sub-command: creates a complete copy of a remote repository on your local machine
https://github.com/...
The URL of the repository to clone. Found on the GitHub page under the green "Code" button.
What happens internally: Git connects to GitHub's servers, downloads all files in the repository, and creates a directory named after the repo in your current directory. A hidden .git/ folder is created storing version history. The download includes ALL versions of all files ever committed.
GIT CLONE COMMANDS

Step 3: Read README.md First!

CRITICAL RULE
Always Read README.md Before Installing
Every GitHub repository has a README.md file with installation instructions specific to that tool. ALWAYS read it first. Run:

ls — see what files are there
cat README.md — read installation instructions
less README.md — paginated view (q to quit)

SECTION 04 // PIP / PIPX / VENV

PYTHON TOOLS

Python is the dominant language in cybersecurity tooling. Understanding pip and virtual environments is essential for every security professional.

CONCEPT // PIP
What Is pip?
pip is Python's package manager — the Python equivalent of APT. It installs Python libraries and tools from PyPI (Python Package Index) at pypi.org.

Always use pip3 (Python 3) not pip (Python 2, outdated). On Parrot OS, pip3 is what you want.
PIP ESSENTIAL COMMANDS
$pip3 install scapy
# Install Python package globally
$pip3 install scapy --user
# Install for current user only (no sudo needed)
# Installed to ~/.local/lib/python3.x/site-packages/
$pip3 install -r requirements.txt
# Install all packages listed in requirements.txt
$pip3 uninstall scapy
# Remove a package
$pip3 list
# Show all installed Python packages
$pip3 show scapy
# Show info about a package
$pip3 install --upgrade scapy
# Update a package to latest version

The Modern Way: pipx

CONCEPT // PIPX
pipx — The Safe Way to Install Python CLI Tools
pipx installs each Python CLI tool in its own isolated environment. This prevents dependency conflicts between tools. It's the recommended way to install Python security tools on Parrot OS.

Newer Parrot OS versions enforce PEP 668, which prevents pip from installing packages system-wide. pipx is the proper solution.
PIPX INSTALLATION AND USAGE
$sudo apt install pipx -y
pipx installed
$pipx ensurepath
# Adds ~/.local/bin to your PATH
Success! Added ~/.local/bin to PATH in ~/.bashrc
$source ~/.bashrc
# Reload shell config to apply PATH change
$pipx install impacket
installed package impacket 0.12.0 (isolated)
$pipx install crackmapexec
installed package crackmapexec
$pipx list
venvs are in ~/.local/pipx/venvs
impacket 0.12.0 (crackmapexec, impacket-...)

Virtual Environments (venv)

CONCEPT // VIRTUAL ENVIRONMENT
Isolating Python Projects with venv
A virtual environment is an isolated Python installation. Each project gets its own Python, its own pip, and its own packages. Changes in one environment don't affect others.

This is crucial when two tools require conflicting versions of the same library.
VIRTUAL ENVIRONMENT WORKFLOW
$python3 -m venv myenv
# Creates a virtual env directory called "myenv"
# Contains its own Python, pip, and site-packages
$source myenv/bin/activate
# ACTIVATE the virtual environment
(myenv) $pip3 install scapy impacket
# Installs ONLY inside this venv, not system-wide
Successfully installed scapy-2.5.0 impacket-0.12
(myenv) $python3 tool.py
# Run your tool with isolated dependencies
(myenv) $deactivate
# Exit the virtual environment, return to normal
$

SECTION 06 // SANDBOXED APPS

SNAP & FLATPAK

Modern sandboxed package formats that bundle an application with all its dependencies. Useful for GUI applications and when you need a specific version isolated from the system.

SNAP
Canonical's Snap Package System
Snaps are self-contained packages that include the app and ALL its dependencies. They run in a sandbox. Developed by Canonical (Ubuntu).

Snaps auto-update. They take more disk space but avoid dependency conflicts entirely.
FLATPAK
Flatpak — Universal Linux App Format
Flatpak is similar to Snap but uses Flathub as its main repository. More common for desktop GUI applications. Works across all Linux distributions.

Also sandboxed — apps run isolated from the system.
SNAP COMMANDS
$sudo apt install snapd -y
$sudo systemctl start snapd
$sudo systemctl enable snapd
# Start and enable the Snap daemon
$snap search burpsuite
$sudo snap install burpsuite
burpsuite (2024.x.x) from PortSwigger installed
$snap list
# List installed snaps
$sudo snap remove burpsuite
$sudo snap refresh burpsuite
# Update a specific snap
FLATPAK COMMANDS
$sudo apt install flatpak -y
$flatpak remote-add --if-not-exists flathub https://dl.flathub.org/repo/flathub.flatpakrepo
# Add Flathub repository — the main Flatpak app store
$flatpak search wireshark

SECTION 07 // MAXIMUM CONTROL

COMPILE FROM SOURCE

Compiling from source gives you the absolute latest code, custom build options, and full control. Required when no pre-built package exists.

CONCEPT // COMPILATION
What Is Compilation?
Source code is human-readable text (.c, .cpp files). Your CPU cannot run it directly. A compiler (like GCC) translates source code into machine code — a binary that your CPU executes.

The compilation pipeline: Source Code → Preprocessor → Compiler → Assembler → Linker → Binary

Step 1: Install Build Tools

INSTALL BUILD ESSENTIALS
$sudo apt install build-essential gcc g++ make cmake autoconf automake libtool pkg-config -y
# build-essential: includes gcc, g++, make, and core dev libraries
# cmake: modern build system alternative to make
# autoconf/automake: generate configure scripts
All build tools installed
$gcc --version
gcc (Debian 13.3.0) 13.3.0

The Classic ./configure && make && make install Pattern

./configure --prefix=/usr/local ▼ EXPLAIN
./configure
Run the configure script from current directory. Checks that all dependencies are present and generates a Makefile tailored to your system.
--prefix=/usr/local
Where to install the compiled program. Default is /usr/local. This means: binary → /usr/local/bin/, libraries → /usr/local/lib/, etc.
What happens: The configure script runs hundreds of small checks — "does libssl exist?", "is gcc version >= 9?", "what architecture are we on?" — and creates a Makefile with all the correct compiler flags and paths for YOUR system.
make -j$(nproc) ▼ EXPLAIN
make
Build automation tool — reads the Makefile and executes compilation commands.
-j$(nproc)
Parallel jobs. $(nproc) returns your CPU core count. So -j4 on 4-core CPU means 4 files compile simultaneously — much faster!
What happens: GCC compiles each .c source file into an object file (.o). Then the linker combines all object files into a single binary executable. This can take seconds to minutes depending on project size.

$sudo make install

$tool --version
tool v1.0.0

DOCKER

Docker lets you run tools in isolated containers — like lightweight virtual machines. Perfect for tools with complex dependencies or when you want complete isolation.

CONCEPT // DOCKER
What Is Docker?
Docker is a containerization platform. A container packages a tool with its entire environment (OS files, dependencies, config) into a single portable unit.

Unlike virtual machines, containers share the host OS kernel — they're much lighter and faster to start. A Docker image is the template. A container is a running instance of an image.

Install Docker

INSTALL DOCKER ON PARROT OS
$sudo apt install docker.io -y
$sudo systemctl start docker
$sudo systemctl enable docker
# start: run now, enable: run on boot
$sudo usermod -aG docker $USER
# Add yourself to docker group → no sudo for docker later
NOTE: Log out and back in for group change to take effect!
$docker --version
Docker version 27.0.3
$docker run hello-world
Hello from Docker! Installation successful!

SECTION 09 // TROUBLESHOOTING GUIDE

ERROR TROUBLESHOOTING

Every beginner will hit these errors. Here's exactly how to fix each one — with the error message, why it happens, and the step-by-step solution.

Troubleshooting Decision Tree

Command not found after installation?
├── YES → Check: echo $PATH — is install dir in PATH?
│ ├── PATH missing dir → Add to ~/.bashrc, run source ~/.bashrc
│ └── PATH has dir → Check: which tool / ls /usr/bin/tool
└── NO (different error)

Permission denied error?
├── Writing to /usr/ or /opt/ → Add sudo before the command
└── Executing a file → chmod +x filename

APT dependency error?
├── broken packages → sudo apt-get install -f
├── outdated lists → sudo apt update first
└── held packages → sudo apt full-upgrade

pip install fails?
├── externally-managed-environment error → Use pipx or --break-system-packages
├── permission denied → pip3 install --user [package]
└── SSL error → pip3 install --trusted-host pypi.org [package]
!
E: Unable to locate package [name]
E: Unable to locate package metasploit-framework

Why it happens: The package name doesn't exist in your current repositories OR your package lists are outdated.

1
Update package lists first: sudo apt update
2
Double-check the exact package name: apt search metasploit
3
If the package exists in search results, try again with the exact name shown.
4
If not found anywhere, the package may need a separate repository. Check the tool's official documentation for APT repo instructions.
5
Enable Parrot OS security repo: check /etc/apt/sources.list for parrot-security entries.
FIX
$sudo apt update
$apt search metasploit
metasploit-framework/parrot-security ...
$sudo apt install metasploit-framework -y
!
Permission Denied
bash: /usr/bin/tool: Permission denied
or: mkdir: cannot create directory '/opt/tool': Permission denied

Why it happens: You're trying to write to a protected system directory without root privileges, OR a file isn't marked as executable.

1
For installation commands: add sudo to the front of the command
2
For executing a file: chmod +x filename then ./filename
3
Check file permissions: ls -la filename — look for 'x' in permissions
FIX
$ls -la tool.sh
-rw-r--r-- 1 parrot parrot 1234 tool.sh
# No 'x' in permissions — not executable!
$chmod +x tool.sh
$ls -la tool.sh
-rwxr-xr-x 1 parrot parrot 1234 tool.sh
# Now has 'x' — executable!
!
externally-managed-environment (pip Error)
error: externally-managed-environment
× This environment is externally managed
╰─> To install Python packages system-wide, try apt install python3-xyz

Why it happens: Parrot OS (Debian-based) implements PEP 668 — it protects the system Python from having packages installed directly with pip3. This prevents pip from breaking APT-managed Python packages.

1
Best solution: Install with pipx (if it's a CLI tool): pipx install package-name
2
Use a virtual environment: python3 -m venv myenv && source myenv/bin/activate && pip3 install package
3
If you must install system-wide (advanced): pip3 install package --break-system-packages
4
Try installing from APT: sudo apt install python3-packagename
!
command not found (after installation)
bash: gobuster: command not found
bash: ffuf: command not found

Why it happens: The tool was installed to a directory not in your $PATH, or you need to reload your shell configuration.

1
Reload your shell: source ~/.bashrc
2
Check PATH: echo $PATH — make sure the install directory is listed
3
Find where it was installed: find / -name gobuster 2>/dev/null
4
Add install dir to PATH: echo 'export PATH=$PATH:~/go/bin' >> ~/.bashrc && source ~/.bashrc
DIAGNOSE AND FIX
$echo $PATH
/usr/bin:/usr/sbin:/bin ← ~/go/bin missing!
$find / -name gobuster 2>/dev/null
/home/parrot/go/bin/gobuster
$echo 'export PATH=$PATH:~/go/bin' >> ~/.bashrc
$source ~/.bashrc
$gobuster --help
# Works now!
!
Broken Packages / dpkg errors
dpkg: error processing package [name] (--install):
subprocess installed post-installation script returned error exit status 1
E: Sub-process /usr/bin/dpkg returned an error code (1)

Why it happens: A previous installation was interrupted, leaving the package database in an inconsistent state.

1
Fix broken packages: sudo apt-get install -f
2
Reconfigure packages: sudo dpkg --configure -a
3
Clean apt cache: sudo apt clean && sudo apt update
4
Force remove broken package: sudo dpkg --remove --force-all [package-name]
FIX BROKEN PACKAGES
$sudo dpkg --configure -a
# Re-run config for all partially installed packages
$sudo apt-get install -f
# -f = --fix-broken : fix dependency issues
$sudo apt clean
# Remove cached .deb files from /var/cache/apt/archives/
$sudo apt update && sudo apt upgrade -y
System clean and updated
!
git clone: SSL certificate / network error
fatal: unable to access 'https://github.com/...': SSL_ERROR_RX_RECORD_TOO_LONG
or: fatal: repository not found

Why it happens: Network connectivity issue, SSL certificate problem, or wrong repository URL.

1
Check internet: ping github.com
2
Verify the URL is correct — copy it directly from GitHub
3
Update CA certificates: sudo apt install ca-certificates -y && sudo update-ca-certificates
4
Try with https vs http, or with .git vs without
!
Missing library / .so file error
error while loading shared libraries: libssl.so.1.1: cannot open shared object file

Why it happens: A required shared library (.so file) is not installed on your system. The tool was compiled against a library version you don't have.

1
Search for the package providing the library: apt-file search libssl.so.1.1 (install apt-file first: sudo apt install apt-file && sudo apt-file update)
2
Try installing the dev package: sudo apt install libssl-dev -y
3
Run ldconfig after installing: sudo ldconfig
!
Go: go: command not found
bash: go: command not found
go install: go binary not in PATH

Why it happens: Go is not installed, or the Go binary directory is not in your PATH.

1
Install Go: sudo apt install golang-go -y
2
Add to PATH: echo 'export PATH=$PATH:/usr/local/go/bin' >> ~/.bashrc && source ~/.bashrc
3
Verify: go version
!
sudo: command not found
bash: sudo: command not found

Why it happens: Rare on Parrot OS, but can happen if using a minimal install. sudo is not installed.

1
Log in as root: su - then enter root password
2
Install sudo: apt install sudo -y
3
Add your user to sudo group: usermod -aG sudo yourusername
4
Log out and back in
SECTION 10 // MAINTAIN YOUR ARSENAL

TOOL MANAGEMENT

Installing is only half the job. Keeping tools updated, removing unneeded ones, and troubleshooting broken tools are equally important skills.

Updating Everything

SYSTEM-WIDE UPDATE COMMAND (RUN WEEKLY)
$sudo apt update && sudo apt upgrade -y && sudo apt autoremove -y && sudo apt autoclean
# This one-liner does everything:
# apt update → refresh package lists
# apt upgrade → upgrade all installed packages
# apt autoremove → remove unused dependencies
# apt autoclean → remove old downloaded .deb files
System fully updated!

Update Tools By Method

UPDATE COMMANDS BY INSTALL METHOD
# === UPDATE BY INSTALL METHOD ===
$sudo apt update && sudo apt upgrade -y
# → APT tools
$cd /opt/toolname && sudo git pull
# → GitHub-cloned tools
$pip3 install --upgrade toolname
# → pip tools
$pipx upgrade-all
# → ALL pipx tools at once
$go install github.com/user/tool@latest
# → Go tools (reinstalls with latest)
$sudo snap refresh
# → ALL snap packages
$flatpak update
# → ALL flatpak apps

Removing Tools

REMOVE TOOLS BY METHOD
# === REMOVE BY INSTALL METHOD ===
$sudo apt remove nmap
# APT remove — keeps config files
$sudo apt purge nmap && sudo apt autoremove
# APT purge — removes EVERYTHING including config
$sudo rm -rf /opt/toolname
# GitHub tool — delete the cloned directory
$pip3 uninstall toolname
# pip tool
$pipx uninstall toolname
# pipx tool
$rm ~/go/bin/toolname
# Go tool — delete binary
$sudo snap remove toolname
# Snap
$sudo rm /usr/local/bin/toolname
# Manually installed binary

Beginner Mistakes Checklist

AVOID THESE COMMON MISTAKES
Top Beginner Errors to Avoid
1. Skipping sudo apt update before installing → outdated packages, errors
2. Not reading README.md before installing from GitHub → missing dependencies
3. Using pip3 system-wide on modern Parrot OS → externally-managed error
4. Forgetting to add GOPATH to PATH → Go tools not found
5. Forgetting source ~/.bashrc after modifying PATH → changes not applied
6. Using root user for everything → security risk, breaks permissions
7. Ignoring error messages → they contain the exact fix
8. Not checking which tool after install → where did it go?
9. Running rm -rf without thinking → unrecoverable deletion
10. Installing with wrong architecture (arm64 vs amd64) → binary won't run

Professional Hacker Tips

🎯
Always check APT first. If a tool is in Parrot's repos, use APT. It handles updates, dependencies, and removal automatically.
📁
Install custom tools in /opt/. This keeps your system organized. Use /opt/toolname/ for GitHub clones and third-party software.
⚡
Use aliases. Create short aliases in ~/.bashrc for long commands: alias update='sudo apt update && sudo apt upgrade -y'
🔒
Verify downloads. Before installing downloaded binaries, check SHA256 checksums: sha256sum file.tar.gz — compare with official hash.
📝
Keep a tools log. Maintain a text file listing all custom-installed tools, their installation method, and location. Saves huge time later.
🐋
Use Docker for noisy tools. Tools that require many conflicting dependencies work perfectly in Docker containers — isolated and clean.
